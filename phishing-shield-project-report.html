1Abstract

Phishing attacks remain one of the most prevalent and damaging forms of cybercrime, responsible for a significant proportion of data breaches worldwide. This project, Phishing Shield, presents a rule-based phishing email detection system that analyses the content, structure, and metadata of any pasted email to determine the probability that it is a phishing attempt.

Built entirely in Python using the Streamlit framework, the system requires no external machine-learning libraries or API keys, making it accessible to beginners while remaining powerful enough for real-world use. The tool assigns a phishing probability percentage (0–100%) and provides a detailed breakdown of every detected risk signal, along with a colour-coded bar chart visualisation.

2Introduction

Email is the most common attack vector for phishing. Attackers craft deceptive messages impersonating trusted organisations — banks, technology companies, government agencies, and delivery services — to steal credentials, personal data, and money. According to the Anti-Phishing Working Group (APWG), millions of phishing attacks are recorded every month globally.

Existing spam filters, while useful, often miss targeted or novel phishing emails. This project addresses that gap by implementing a multi-layer detection engine that analyses emails from several independent angles simultaneously — urgency language, threat vocabulary, financial fraud patterns, brand impersonation, typographical tricks, and structural anomalies.

Objectives

  • Detect phishing emails with high accuracy across diverse attack types.
  • Handle real-world email formats pasted from Gmail, Outlook, and Apple Mail.
  • Detect homoglyph (look-alike character) impersonation — e.g. PayPaI, InvoIcing.
  • Provide human-readable explanations of every detected risk signal.
  • Avoid false positives on legitimate newsletters, receipts, and institutional emails.
  • Keep the entire system in a single Python file suitable for beginners.

Stage 1 — Email Pre-Processor

When a user pastes an email from their email client, the raw text contains client-generated UI artefacts: timestamps, "Inbox" labels, "Unsubscribe" buttons, social media footer icons, and image placeholder tokens. The pre-processor strips all of these line-by-line using regular expressions before the detection engine runs, preventing false positives from newsletter footer content such as "Facebook Instagram YouTube LinkedIn".

It also extracts structured fields (From, To, Subject) from both standard RFC-822 header format and Gmail's display-name format (Name <email> Unsubscribe), which are shown to the user as a parsed-fields panel above the results.

Stage 2 — Detection Engine (14 independent checks)

Each check runs independently on the cleaned email text and contributes a weighted score to the final total. Checks are grouped into categories as described in Section 4.

Stage 3 — Scorer & UI

All check scores are summed and clamped to 100. The final percentage is classified into three verdict bands: High Risk (≥65%), Moderate Risk (30–64%), and Low Risk (<30%). The Streamlit UI renders the verdict, a metrics row, detailed per-signal cards, and an inline SVG bar chart — all without any external charting library.

4Detection Checks

2 Threat / Fear Tactics High Account suspension threats, legal action, collections department, "temporary suspension of services", security breach language.
3 Reward / Greed Bait High Prize claims, lottery wins, inheritance offers, wire transfer requests, Western Union mentions.
4 Credential / Data Harvesting High Requests for passwords, credit card numbers, CVV, SSN, PIN, bank details, date of birth.
5 Suspicious / Malicious URLs High IP-address links, URL shorteners (bit.ly, TinyURL), fake subdomain patterns, shady TLDs (.xyz, .top), compound portal domains (-billing-center, -service-portal).
6 Financial Fraud / Invoice Scam High Overdue invoice language, "outstanding balance", "final notice", "legal proceedings", billing portal domains, "collections department".
7 Brand Name Typo / Lookalike High 200+ curated typo variants of 40 major brands — paypa1, g00gle, amaz0n, microsofft, netfliix etc. Checks the normalised text so homoglyphs are caught too.
8 Typosquatted Domain (Fuzzy Match) High Each hyphen-separated token of every URL/sender domain is tested against all known brand domains using Levenshtein edit-distance (≤1 after normalisation). Catches novel typosquats not in the curated list.
9 Brand / Domain Mismatch High A known brand name appears in the email body, but no link or sender domain belongs to that brand's official domain. Social media brands are excluded (newsletter footers).
10 Homoglyph in Sender Name High The display name uses visually identical characters mid-word (capital I instead of l, 0 for o, 1 for l). e.g. "InvoIcing Department", "PayPaI Support". Detected by a normalisation diff on each word.
11 Generic / Impersonal Greeting Medium "Dear Customer", "Dear User", "Dear Account Holder" — legitimate companies address recipients by name.
12 Spelling Mistakes Low–Med 20+ common phishing template misspellings: recieve, adress, untill, beneficary, occured, wierd, etc.
13 Formatting / Aggressive CAPS Low Excessive ALL-CAPS words (filtered against a whitelist of legitimate acronyms), repeated exclamation marks, double question marks.
14 Grammar & Structure Issues Low Missing spaces after punctuation (≥3 occurrences), repeated adjacent words, very long unbroken paragraphs.

9Key Algorithms

9.1 Homoglyph Normalisation

Before any brand comparison, the email text is passed through a character translation table (str.maketrans) that substitutes visually identical characters: capital I→l, digit 0→o, digit 1→l, digit 3→e, and others. This causes "PayPaI" and "PayPal" to compare as identical, detecting the attack.

9.2 Levenshtein Edit-Distance Fuzzy Matching

Each URL and sender email domain is first split on hyphens — so "paypai-resolution-center-security.com" becomes tokens ["paypai", "resolution", "center", "security"]. Each token is then compared to every known brand domain core using a custom dynamic-programming Levenshtein implementation. An edit distance of 0 or 1 after normalisation is flagged as a typosquat.

9.3 Multi-layer Brand Mismatch

Brand impersonation is caught at three independent layers: (1) exact typo-variant lookup in a curated map, (2) fuzzy edit-distance on domain tokens, and (3) brand name appears in the body but no extracted domain belongs to that brand's official domain. All three run independently — any one is sufficient to flag the email.

10Limitations

  • The system uses heuristic rules, not machine learning — it cannot learn from new phishing patterns automatically.
  • Sophisticated phishing emails that avoid all keyword patterns may produce lower scores.
  • The brand database covers 40 companies; impersonation of unlisted organisations is only caught by generic checks.
  • The spelling checker uses a fixed word list; it does not use a full NLP dictionary.
  • Image-based phishing emails (where all text is inside an image) cannot be analysed without OCR integration.
  • No live URL scanning — suspicious URLs are detected by pattern, not by checking if the link is actually malicious.

11Future Scope

  • Machine Learning integration — train a classifier (e.g. Naive Bayes or BERT) on a labelled phishing dataset (CEAS-08, SpamAssassin) to improve accuracy.
  • Live URL reputation check — integrate with Google Safe Browsing API or VirusTotal API to verify URLs in real time.
  • Browser extension — port the engine to a Chrome/Firefox extension that analyses emails directly in Gmail or Outlook Web.
  • Attachment analysis — detect malicious file extensions and macro-enabled Office documents attached to emails.
  • Multi-language support — extend keyword lists to Hindi, French, Spanish, and other languages.
  • DKIM / SPF header verification — parse raw email headers to verify sender authentication records.
  • Cloud deployment — host on Streamlit Community Cloud for public access with no local installation.

12Conclusion

Phishing Shield successfully demonstrates that a highly capable phishing detection system can be built using pure Python with no external AI libraries. By combining 14 independent heuristic checks — including homoglyph normalisation, Levenshtein fuzzy domain matching, financial fraud vocabulary, a 40-brand impersonation database, and an email pre-processor that handles real-world pasted email formats — the system achieves strong detection accuracy across a broad range of phishing attack types.

The system correctly scores all tested phishing emails at 72–100% while keeping legitimate emails from real senders at 0–25%, demonstrating effective separation between malicious and benign content. The entire implementation in a single Python file makes it an ideal learning project for students entering the field of cyber security.
